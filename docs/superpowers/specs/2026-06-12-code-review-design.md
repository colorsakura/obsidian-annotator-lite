# 代码质量审查计划

**日期**: 2026-06-12
**范围**: 全项目代码质量审查
**深度**: 标准审查
**方法**: 并行多维度审查

---

## 目标

对 obsidian-annotator-lite 项目进行全面的代码质量审查，识别并清理：

- 死代码和未使用的导出
- 未使用的依赖和过时版本
- 类型定义问题
- 孤立文件

## 审查维度

### 1. 死代码检测

**检查内容**:

- 未使用的导出函数/类/变量
- 未使用的 import 语句
- 注释掉的代码块
- 不可达代码

**范围**: `src/**/*.ts`, `src/**/*.tsx`

**工具**: ESLint `no-unused-vars` 规则 + 手动检查

### 2. 依赖健康

**检查内容**:

- `package.json` 中声明但未使用的依赖
- 可能过时的依赖版本
- 对 bundle 大小的影响

**范围**: `package.json`, `node_modules/`

**工具**: `bun pm ls`, 手动交叉引用 import

### 3. 类型完整性

**检查内容**:

- `any` 类型的使用（是否必要）
- `src/types/foliate-js.d.ts` 简化是否导致类型缺失
- 类型断言 (`as`) 的合理性

**范围**: `src/**/*.ts`, `src/**/*.tsx`, `src/types/`

**工具**: TypeScript 编译器 + 手动检查

### 4. 未使用文件

**检查内容**:

- 未被任何模块引用的文件
- 临时文件、备份文件
- 测试残留

**范围**: `src/`

**工具**: import 追踪 + 文件交叉引用

## 预期产出

每维度产出：

1. **问题列表** - 文件路径 + 行号 + 问题描述
2. **严重程度** - Critical / Warning / Info
3. **清理建议** - 可直接执行的操作

## 执行策略

四个维度并行执行，各自独立扫描，最后汇总报告。

## 范围限制

- 仅审查 `src/` 目录
- 不涉及功能变更
- 不修改业务逻辑
- `node_modules/` 只在依赖检查时参考
